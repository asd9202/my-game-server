# 장애 대응 훈련 리포트

## 1) 목적

- 실제 서비스 장애와 유사한 상황에서 복구 동작을 검증한다.
- 통제된 장애 주입으로 MTTR과 재접속 성공률을 측정한다.
- 의존성 저하 상황에서도 World tick 안정성을 확인한다.

## 2) 범위

- 서비스: Login, Gateway, World, Chat.
- 의존성: MySQL, Redis, MongoDB.
- 환경: local compose 또는 k8s dev.

## 3) 성공 기준

| 메트릭 | 목표 |
|---|---:|
| MTTR | <= 90s |
| 재접속 성공률 | >= 95% |
| 데이터 유실 (chat/action logs) | 테스트 구간 0 |
| 장애 중 Tick drift p95 | 평시 대비 < 2.5배 |

## 4) 훈련 시나리오

### 시나리오 A - Gateway Pod 강제 종료

- 가설: 토큰/세션 플로우를 통해 최소 중단으로 재접속이 가능하다.
- 주입 방법:
  - k8s: `kubectl delete pod <gateway-pod>`
  - compose: gateway 컨테이너 중지
- 기대 결과:
  - 재접속 성공률 >= 95%
  - 영구 세션 고아(orphan) 없음

### 시나리오 B - World Pod 재시작

- 가설: 플레이어 상태 재바인딩과 world attach 복구가 동작한다.
- 주입 방법:
  - 활성 세션 중 world 인스턴스 재시작
- 기대 결과:
  - 활성 플레이어 상태 복원 성공
  - 복구 시간 상한 내 완료

### 시나리오 C - MongoDB 지연 급증

- 가설: 비동기 로그 라이터 큐가 지연을 흡수하고 게임 루프는 안정적이다.
- 주입 방법:
  - Mongo 네트워크 경로에 인위적 지연 추가
- 기대 결과:
  - queue backlog 증가 후 정상 배출
  - world tick이 목표 범위 유지

### 시나리오 D - Redis 장애

- 가설: 재접속/세션 조회가 fallback으로 전환되어 점진적 저하로 동작한다.
- 주입 방법:
  - Redis를 N초 동안 중단
- 기대 결과:
  - 제어된 에러 응답 반환
  - crash loop 없음
